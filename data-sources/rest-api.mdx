Softr’s **REST API data source** allows you to connect to almost any platform, database, or service. If Softr doesn’t natively support your data source, you can likely still integrate it using the **REST API connector**.

With the REST API connector, you can:

* Import **real estate listings from Zillow, inventory from Shopify, or invoices from Stripe**

* Connect to **public APIs** (for example, APIsList, Public APIs, or RapidAPI)

* Integrate **new CRMs and productivity tools**

* Fetch and create data using any **standard HTTP REST API**

<Info>Rest API is available on Business and Enterprise plans.</Info>
<Tip>

REST API is not a supported data source for the [Users](/add-and-manage-users/pxnkp9H3qyEVMF6XUceqnj/syncing-users-with-a-data-source/hshRGygHr4T33EnaLntGf9) of your application.

</Tip>

## **1. Connect a REST API to Softr**

You connect a REST API once per workspace. Then you can use it in all your apps.

<Steps>
  <Step title="Open Integrations">
    1. In the Softr Studio dashboard, click **Integrations** in the left menu.

    2. Click **Connect new**.

    <Frame>![The Integrations page of the dashboard, with the Connect new button](/data-sources/images/rest-api/integrations.png)</Frame>

    3. In the **Select an integration** window, click **Rest API**.

    <Frame>![The Select an integration window, with Rest API selected](/data-sources/images/rest-api/select-integration.png)</Frame>
  </Step>
  <Step title="Connect your account">
    Fill in the **Connect your account** window:

    1. **Provider**: Enter a name for the API, for example "Stripe". You'll see this name in your list of integrations.

    2. **Authentication type**: Select **API key** or **OAuth**. The API's own documentation tells you which one it uses.

    3. **Base URL**: Enter the root address of the API, for example `https://api.stripe.com`. The base URL is optional. The Vibe Coding block needs it.

    4. Fill in the fields of your authentication type (see below).

    5. Click **Continue**.

    <Frame>![The Connect your account window for a Stripe API key](/data-sources/images/rest-api/connect-api-key.png)</Frame>

    **API key**

    * Select **Bearer token** when the API expects `Authorization: Bearer <key>`. Then paste the key in **API key**.

    * Select **Custom header** when the API expects the key in another header. Enter the header name in **Header**, then paste the key in **API key**.

    The blue box shows the exact header that Softr sends with every request.

    **OAuth**

    1. Copy the **OAuth Redirect URL** and add it to the OAuth app settings of the API.

    2. Enter the **Authorization URL**, the **Access token URL**, the **Client ID**, the **Client secret**, and the **Scopes** from the API's documentation.

    3. If the API needs extra parameters, turn on **Advanced settings**. Then add the authorize, access token, or refresh token parameters.

    4. Click **Continue**, then sign in to the API in the window that opens.

    <Frame>![The Connect your account window with OAuth selected](/data-sources/images/rest-api/connect-oauth.png)</Frame>

    <Warning>

    **Important**: Each API works differently. This page shows how Softr's REST API connection works. It isn't a step-by-step guide for one specific API.

    If you need help with an API beyond the scope of this page, reach out to one of our [Certified Softr Experts](https://www.softr.io/softr-experts). They can guide you or build it for you.

    </Warning>
  </Step>
  <Step title="Add API resources (endpoints)">
    A resource is one API call that you save and reuse in your apps, for example "Invoices" or "Create invoice". Resources support the **GET** and **POST** methods.

    1. On the **Integrations** page, click the **...** menu of your REST API integration.

    2. Click **Edit resources**.

    <Frame>![The menu of a REST API integration, with Edit resources](/data-sources/images/rest-api/edit-resources.png)</Frame>

    3. In the **Resources** window, click **Add**.

    <Frame>![The Resources window of the Stripe integration, with five resources](/data-sources/images/rest-api/resources.png)</Frame>

    <Tip>

    You can also add a resource from a block. In the block's **Source** tab, open the **Resource** dropdown and click **Add resource**.

    </Tip>

    4. Fill in the resource:

    * **Name**: A name that helps you find the resource in the list.

    * **HTTP method**: **GET** to read data, or **POST** to send data. Use the method from the API's documentation.

    * **URL**: The endpoint that Softr calls, for example `https://api.stripe.com/v1/invoices`.

    5. Click **Execute** to send a test request to the API.

    <Frame>![A new resource with its name, HTTP method, URL, and the Execute button](/data-sources/images/rest-api/resource-form.png)</Frame>

    6. When the test request succeeds, click **Save**.

    <Info>

    Softr saves a resource only after a successful **Execute**. When you change the request (URL, headers, URL params, placeholders, body, or pagination), click **Execute** again.

    </Info>

    <Tip>

    You'll often need the optional sections and the schema too. Read the sections below before you save.

    </Tip>
  </Step>
</Steps>

## **2. Configure the optional sections**

Below the **Execute** button, the resource has more sections. Turn on a section with its toggle. Every API is different, so you may need all of these sections or none of them. Check the API's documentation.

### **Headers**

The **Headers** section always shows the authentication header of the integration. Click **Add** to add a header that only this resource needs.

<Frame>![The Headers and URL params sections of a resource](/data-sources/images/rest-api/headers-url-params.png)</Frame>

### **URL params**

Use **URL params** to add query parameters to the URL. Add each parameter as a name and a value. You can also type them in the URL field, but this section keeps them easier to read and change.

Find the parameter names and values in the API's documentation. In the example above, the `customer` parameter tells the Stripe invoices endpoint to return the invoices of one customer:

<Frame>![The customer parameter in the Stripe documentation for listing invoices](/data-sources/images/rest-api/stripe-invoices-docs.png)</Frame>

A parameter value can be static or dynamic. The customer changes with the person who is logged in. Thus the example uses the placeholder `{LOGGED_IN_USER:StripeID}`. Softr replaces it with the `StripeID` field of the logged-in user.

### **Placeholders**

Placeholders send dynamic data to the API, based on the logged-in user, the selected record, or the filters and search of a block. Write a placeholder in curly braces, for example `{placeholderName}`, in the URL, the URL params, or the body.

You can use three kinds of dynamic placeholders:

* `{LOGGED_IN_USER:<FIELD NAME>}`: Sends a field of the logged-in user.

* `{recordId}`: Sends the ID of the selected record.

* `{filter.<FIELD NAME FROM API>}`: Sends the value of a search or filter in a block.

When a request has placeholders, the **Placeholders** section lists them. Enter a sample value for each one, so that **Execute** can test the request. Your live app doesn't use these sample values.

<Frame>![The Placeholders section with a sample value for the logged-in user's Stripe ID](/data-sources/images/rest-api/placeholders.png)</Frame>

Use a `{filter.<FIELD NAME FROM API>}` placeholder to filter or search the API from a block. In the example below, the **Search customers** resource sends the search text to Stripe in the `query` URL param:

<Frame caption="Use the filter placeholder to filter by dynamic values against the API.">![A resource that sends the filter.email placeholder in a URL param](/data-sources/images/rest-api/filter-placeholder.png)</Frame>

Then turn on the search bar of the block in its **Content** tab:

<Frame caption="Turn on the search bar of the block so that people can search the API.">![The List block settings with the search bar turned on](/data-sources/images/rest-api/block-search.png)</Frame>

<Tip>

Softr treats anything inside `{}` as a placeholder.

`{LOGGED_IN_USER:<FIELD NAME>}` sends data of the logged-in user in the API request.<br/>
`{filter.<FIELD NAME FROM API>}` filters by a dynamic value, if the API supports it.<br/>
`{recordId}` sends the current record in the API request.

</Tip>

### **Body**

The **Body** section shows when the HTTP method is **POST**. Use it to send data to the API, for example from an **Add record** button on a List block. Write the body as JSON. Use the API's documentation to know which keys to send.

In this example, the **Create invoice** resource creates a Stripe invoice for the logged-in user:

<Frame>![The Body section of a POST resource that creates a Stripe invoice](/data-sources/images/rest-api/body.png)</Frame>

### **Pagination**

Most APIs return a limited number of records per request. Use the **Pagination** section to tell Softr how to get the next page of results. Softr uses cursor pagination:

* **Response parameter - cursor**: Where the cursor of the next page is in the response (**Body** or **Header**), and its name. Turn on **Transformer function** if you need JavaScript to read the cursor.

* **Request parameter - cursor**: Where Softr sends the cursor in the next request, and the parameter name.

* **Request parameter - limit**: The parameter that sets the number of records per page, and its value.

In the Stripe example, Softr sends the ID of the last invoice as `starting_after`, and asks for 25 invoices per page with `limit`.

<Frame>![The Pagination section with the cursor and limit parameters for Stripe](/data-sources/images/rest-api/pagination.png)</Frame>

### **Transformer**

Use the **Transformer** section to change the API response with JavaScript. A transformer can extract a nested list from the response, or calculate a new field. AI tools are good at writing these functions.

In the Stripe example, `return response.data;` keeps only the list of invoices in the `data` key of the response.

<Frame>![The Transformer section with return response.data](/data-sources/images/rest-api/transformer.png)</Frame>

## 3. Check the response and the schema

When you click **Execute** and the request succeeds, three tabs show below the sections: **Schema**, **Transformed JSON**, and **Raw JSON**. Scroll down to see them.

**Schema**

The **Schema** tab lists the fields of the response. Softr Studio shows these fields when you set up a block. Each field has four settings:

1. **Key**: The name of the field in the response.

2. **Type**: How Softr shows and filters the field. The types are TEXT, NUMBER, BOOLEAN, DATE, DATETIME, TIMESTAMP, OBJECT, ARRAY, EMAIL, and URL.

3. **Enabled**: Clear this checkbox to hide the field in Softr Studio.

4. **Is ID field**: Turn on this toggle for the field that identifies each record. When no field is the ID field, Softr shows a warning.

<Frame>![The Schema tab with the Key, Type, Enabled, and Is ID field settings](/data-sources/images/rest-api/schema.png)</Frame>

**Transformed JSON**

The **Transformed JSON** tab shows the response after your transformer runs. The **Schema** tab is built from this JSON.

<Frame>![The Transformed JSON tab with the list of Stripe invoices](/data-sources/images/rest-api/transformed-json.png)</Frame>

**Raw JSON**

The **Raw JSON** tab shows the response exactly as the API sent it. Check this tab first: it shows which transformer you need, if any. In the Stripe example, the invoices are in the `data` key, so the transformer returns `response.data`.

<Frame>![The Raw JSON tab with the full Stripe response](/data-sources/images/rest-api/raw-json.png)</Frame>

## **FAQs**
   <AccordionGroup>
   <Accordion title="Can I use REST API to update data in Softr?">
Yes! You can use **POST** requests to create new records.
   </Accordion>
   <Accordion title="How do I add authentication for my API?">
Select **API key** or **OAuth** when you connect the API. Softr adds the authentication header to every request.
   </Accordion>
   <Accordion title="Can I connect multiple APIs to one Softr app?">
Yes! You can add multiple REST API connections and use them across different blocks.
   </Accordion>
