## Overview

### Adding the Button

This [action button](/actions/ntEfT9zSJk6aY54G6W5KGU/action-buttons-overview/idg8Fqf2kjFwcx6kyP3jNq) is available under **Topbar Buttons**. It lets users add new records to your data source, such as a [Softr Database](/softr-databases/softr-databases-overview) table. Add record buttons are available on List blocks. To add one, select the List block, open the **Actions** tab, click **+ Add Topbar Button**, and choose **Add Record** from the dropdown.
<Frame>![The Actions tab of a List block with the Add topbar button option highlighted](/actions/images/add-record/image1.png)</Frame>
<Tip>By default, your block has one **Add record** button. You can remove it.</Tip>

### Adding Form Fields

Users need fields to fill in when they add a record. Once you add the button, you can:

1. Give the button a label.

2. Add the fields that users fill in for the new record. Each field has a label, a placeholder, a required switch, and a **Map to** setting that links it to a field in your data source.
<Frame>![The Actions tab of a List block with an Add record button and its fields](/actions/images/add-record/image2.png)</Frame>

### About the Modal

The modal is the form that users see when they add a record. You can set the title of the **Add Record** modal and the text of its Add and Cancel buttons. To see the live form, preview the app or use it live. You can also preview the modal with the eye icon in the upper right of the section. To change the look of the modal (background, text color, button color), use the [Theme](/styling/7qXYEkNvWQamR6vcLXzZnF/application-theme/91YGSL2aDJajXdbPBhitbc) menu tab.
<Frame>![The settings of the Add record modal: title and button texts](/actions/images/add-record/image3.png)</Frame>

### Setting the On Form Submission

Here you set the success message that users see after they submit the form, and the action that runs next. You can choose:

* **Open new record’s details page:** Sends the user to a details page for the new record. If you have no details page for this type of record, Softr asks you to create one.

* **Close the modal:** Closes the popup and returns the user to the screen they came from.

* **Open a page:** Sends the user to a page in your app.

* **Open an external URL:** Sends the user to a URL you set.
<Frame>![The On form submission settings: success message and next action](/actions/images/add-record/image4.png)</Frame>

### Button Visibility

After you create the button, click the yellow branching icon to set visibility conditions based on the logged-in user’s [user group](/user-groups-and-permissions/3oA6AaFzUiePs2sW2TpYrF/user-groups/6XQfKMeKHUvBcAjKvLs3g3).
<Frame>![The branching icon that opens the button visibility settings](/actions/images/add-record/image5.png)</Frame>

## Example

Let’s set up this action. We use a [List block](/building-blocks/vikC2AWEpQGkZd4jGyoVxo/list-block/pQhPYuA28VXr5tLLFBcbCU) connected to a Tasks table in a [Softr Database](/softr-databases/softr-databases-overview). The list shows the tasks of a product development team. Each task has a **Task** name, a **Status** (the progress of the task), and a **Priority**. The table can have more fields. We want an “Add new task” button so team members can add tasks to the list.
<Frame caption="List of tasks">![List of tasks](/actions/images/add-record/image6.png)</Frame>

First, we set the button label.
<Frame caption="Button label">![Button label](/actions/images/add-record/image7.png)</Frame>

Then we customize the other texts of the button. The following gif also shows how to preview the **Add record** pop-up, where users enter the details of a new record.
<Frame caption="Setting up button texts and previewing the modal">![Setting up button texts and previewing the modal](/actions/images/add-record/image8.gif)</Frame>

Next, we choose which fields of the data source users fill in. Click **Add field** in the button settings and add each field. A new task needs a **Task** name, a **Status**, and a **Priority**. We add a Text field and map it to the **Task** field of the table. We add two dropdown fields and map them to **Status** and **Priority**, because both are select fields in the table.
<Frame caption="Adding fields for the add new task functionality">![Adding fields for the add new task functionality](/actions/images/add-record/image9.gif)</Frame>
<Info>You can also add a [Signature field](/displaying-and-creating-data/vikC2AWEpQGkZd4jGyoVxo/layout-customizable-form/jCim5VWZePgZuaRsUZBnpG#signature-field) to capture eSignatures when users add records.</Info>
<Warning>Computed fields, such as formula, lookup, and rollup fields, don’t appear in the list of mappable fields for the form.</Warning>
<Warning>You can’t add or edit records in synced tables.</Warning>

Now we define who can see and use the button (see [button visibility](/user-groups-and-permissions/3oA6AaFzUiePs2sW2TpYrF/action-button-visibility/tqpb8TkUD4U4DCAUA2hjKo)).

<Tip>
Button visibility options depend on the subscription plan:

→ On Free and Starter plans you can decide who can see the button (All Users, Logged-in Users, or Non Logged-in Users)

→ On the Professional plan you can also configure conditional visibility, but you can’t set [custom user groups](/user-groups-and-permissions/3oA6AaFzUiePs2sW2TpYrF/user-groups/6XQfKMeKHUvBcAjKvLs3g3).

→ On the Business plan you have access to all the features in Button Visibility.
See [plan comparison](https://www.softr.io/pricing).
</Tip>

The users of our task list are the team members who work on those tasks. Their emails are in the **Assignee email** field of the Tasks table, next to each task.
<Frame caption="The Tasks table in a Softr Database: each task has a status and an assignee email.">![The Tasks table of a Softr Database with the fields Task, Details, Status, Priority and Assignee email](/actions/images/add-record/tasks-table-softr-databases.webp)</Frame>
<Tip>Users who sign in to your app must exist as [users in Softr](/add-and-manage-users/pxnkp9H3qyEVMF6XUceqnj/users-menu/5JTzjtbvp8Skemd26A9ho9). If your users live in another data source, see [Syncing users with a data source](/add-and-manage-users/pxnkp9H3qyEVMF6XUceqnj/syncing-users-with-a-data-source/hshRGygHr4T33EnaLntGf9).</Tip>

We also create a [user group](/user-groups-and-permissions/3oA6AaFzUiePs2sW2TpYrF/user-groups/6XQfKMeKHUvBcAjKvLs3g3) for project managers only.
<Frame caption="Creating a user group for project managers.">![Creating a user group for project managers.](/actions/images/add-record/image11.png)</Frame>

Next, we set the button visibility so that only the **Project Managers** user group can see the button.
<Frame caption="Setting button visibility">![Setting button visibility](/actions/images/add-record/image12.gif)</Frame>

Now let’s test the setup from the user’s side.
