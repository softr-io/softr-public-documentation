Conditional filters show only the records that meet the conditions you define. They work on the List block and on other dynamic blocks.

<Info>Conditional filtering is also used when you want to display a main list of items, and upon selecting a specific item, show its details along with its associated sub-items. Learn about [Linked List](/building-blocks/vikC2AWEpQGkZd4jGyoVxo/linked-list/bWjTdKhbftofSEKRSxMFz9). </Info>

In the Studio, this section is called **Record filters**. Find it in the **Source** tab of the block settings. See also [Record filters](/user-groups-and-permissions/record-filters).
<Frame caption="The Record filters section in the Source tab of a block.">![The Record filters section with the any-or-all selector and the Add condition button](/user-groups-and-permissions/images/conditional-filters/record-filters-section.webp)</Frame>

First, use the dropdown at the top to choose whether **any** or **all** of the conditions must be met.
<Frame caption="“Any” or “All” of the conditions">![The any-or-all dropdown with Any and All options](/user-groups-and-permissions/images/conditional-filters/any-or-all.webp)</Frame>

Extra conditions join with:

* AND (when "All" is selected)

* OR (when "Any" is selected)
<Frame caption="The second condition starts with And when “All” is selected.">![A second condition joined with And](/user-groups-and-permissions/images/conditional-filters/and-condition.webp)</Frame>

Each condition has three parts: a field, a condition, and a value.

## **1. Field**

Select the field of the data source table that the condition tests.

## 2. Condition
<Frame caption="The conditions available for a text-like field.">![The condition dropdown listing Is, Is not, Contains, Does not contain, Is any of, Is none of, and Is empty](/user-groups-and-permissions/images/conditional-filters/condition-operators.webp)</Frame>

The condition describes how the field relates to the value. The available conditions depend on the field type.

**Text-like fields**, such as emails, formulas, URLs, and single select fields, can be used with the following available conditions:

* **Is** – the Field value needs to match the Valueexactly

* **Is not** – the Field value has any value apart from the Value

* **Contains** – the Field value partially matches the Value

* **Does not contain** - the Field value doesn’t partially match the Value. It checks if the given Value is not present within the Field value

* **Is any of** –the Field value is any of the Value(s). Multiple values can be added

* **Is none of** – the Field values have any other value apart from the Value(s). Multiple values can be added

* **Is empty** – the Field value is empty

* **Is not empty** – the Field value is not empty. Has some value

* **Starts with** – the Field value starts with the Value

* **Ends with** – the Field value ends with the Value

**Numeric fields** can be used with the following available conditions:

* =

* ≠

* \>

* \<

* ≥

* ≤

* Is between *(inclusive of min/max)*

* Is empty

* Is not empty

**Array-like fields**, such as multi-select fields, linked records, tags, and lookup fields, can be used with the following available conditions:

* Includes any of

* Includes all of

* Includes exactly

* Includes none of

* Is empty

* Is not empty

**Boolean fields**, such as checkbox fields:

* Is

* Is not

* Is empty

* Is not empty

<Info>Date fields currently use the same conditions as text-like fields.</Info>

## 3. Value

You have two options.

### Entering a specific value

Enter a value. The block then shows only the records that have that value.

<Tip>If the **value contains a space**, you'd need to copy it from somewhere else instead of typing it in.</Tip>

For example, a Tasks table in [Softr Databases](/softr-databases/softr-databases-overview) has a Status field. To show only the tasks in progress, set the condition to **Status is In progress**.
<Frame caption="A Tasks table with Task, Details, Status, Priority, and Assignee email fields.">![A Tasks table in Softr Databases with Status and Assignee email columns](/user-groups-and-permissions/images/conditional-filters/tasks-table-status-and-assignee.webp)</Frame>

### **Using Logged-in user's parameters**

Use this option to filter the block for each logged-in user, so that each user sees only their own records.

By default, you can use the user's **Email** and **Email domain**. If you've [connected users to a data source](/add-and-manage-users/pxnkp9H3qyEVMF6XUceqnj/syncing-users-with-a-data-source/hshRGygHr4T33EnaLntGf9), all the fields of that data source are available too.

Here is an example. The Tasks table has the fields **Task**, **Status**, and **Assignee email**. The Assignee email field holds the email of the user who owns the task.

Each user should see only their tasks. One condition does this. Set the **Field** to **Assignee email** and the value to the **logged-in user's Email**. The block then shows only the tasks where Assignee email matches the email of the user who is logged in.
<Frame caption="One table and one condition give each user a different view.">![Maria sees her three tasks and Leo sees his three tasks, from the same Tasks table with the same record filter](/user-groups-and-permissions/images/conditional-filters/record-filter-per-user.webp)</Frame>

You can set a condition like this for any field of your block.

<Tip>Softr plans to add more user attributes for filtering, such as user roles and statuses.</Tip>

### Use Case: **Using a Checkbox field in a Conditional Filter**

You can filter on a Checkbox field.

<Tip>The List block can't display a Checkbox field (the [Table](/building-blocks/vikC2AWEpQGkZd4jGyoVxo/table-block-/j7rGwu7J7zuU69h3bZ7HFe) block can). You can still use it in a conditional filter without displaying it.</Tip>

To show the records with the checkbox checked, use the **is not empty** condition. To show the unchecked records, use **is empty**.
<Frame caption="“is not empty” shows the checked items.">![A condition on a checkbox field with the is not empty operator](/user-groups-and-permissions/images/conditional-filters/checkbox-is-not-empty.webp)</Frame>
